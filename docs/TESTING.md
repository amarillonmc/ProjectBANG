# 内测版验证记录

日期：2026-09-05。运行环境为 Windows、本机 PHP 7.4.33 + PDO SQLite、Node.js 语法检查，以及 Codex 内置 Chromium 浏览器。代码推荐部署到受支持的 PHP 8.2+，但本次没有将其宣称为已经完成所有 PHP 8.x 版本或真实主机的兼容测试。

## 自动验证

```sh
php tests/engine.php
php tests/audit-api-engine.php
php tests/properties.php
php -d extension=pdo_sqlite tests/api.php
node --check public/assets/app.js
php -d extension=pdo_sqlite tools/doctor.php
```

如果 PHP 已启用所需驱动，可以省略 `-d extension=pdo_sqlite`。正式游戏不需要 Node；这里只用它检查 JavaScript 语法。API 测试需要 PHP CLI 的 curl 与 proc_open，用于启动两个本地临时 HTTP worker，数据库为独立临时 SQLite，不会清空正式 `var/game.sqlite`。

## 有意义的边界覆盖

- 原帖普通牌的104张分布、A～K点数、限定牌与通用牌合法构筑。
- 技能白名单、严格类型、数值上限、未知字段、超额预算、过多技能/限定牌、错误点数、非法动作原子回滚。
- 防守、躲避、拳击、装备成熟、心坏、精神回复、无色削身体、系列伤害、翻面和奇迹救援。
- 延时判定、群体事件、攻守同盟反制、轮选剩牌回收、跨系列限定牌变为装备后再恢复原牌、跨玩家心象归属。
- 来源中途出局时队列继续，赠牌按归属弃置，死者不获得新手牌。
- 隐藏手牌不能通过猜测实体UID指定弃置；视角不包含对方手牌、顺序心象或未来普通牌。
- 随机身份凭证服务器只存哈希、未参与者不能窥视房间、非房主不能开局、构筑只能由所属用户修改。
- 开局快照冻结、刷新恢复、过期版本冲突、同requestId重试不重复执行、同ID异载荷拒绝。
- 两独立PHP worker同时写同revision：一个成功、另一个409，房间只增加一个版本。
- 进行中导出脱敏、反馈存储、限流、事务失败回滚、两种数据库配置路径的代码分支。

## 浏览器人工验收

在本机网页实际操作并观察结果：

- 首页插画、角色选择、私人房间与练习入口。
- 输入昵称建立身份，自动加入两名机器人并开始对局。
- 刷新后恢复原身份和房间。
- 普通牌/心象混合摸牌、永续牌装备、心象攻击与目标选择、真人响应、倒计时和机器人推进。
- 通过积木将受伤摸牌从1改为2、更名角色与限定心象、调整限定牌位置并保存；后台确认定义与顺序一致。
- 将刚保存的自创构筑带入真实练习房，牌桌显示新名字、技能与心象顺序。
- 规则与牌库、预算预览、桌面与390×844手机布局。
- 浏览器控制台检查无未处理脚本错误。
- 实际提交一条关联房间的内测反馈，确认服务端接收并显示成功提示。

联调中实际发现并修复了请求结束后动作按钮保持禁用、手机牌桌网格横向撑开、自身延时区缺失、部分响应同名卡辨识和昵称弹窗字段定位等问题。

## 尚未验证与使用边界

- **真实MySQL/MariaDB连接未验证**。PDO/InnoDB路径已实现，SQLite路径已经完整运行。若选择MySQL部署，须在你的主机上执行部署文档的首次验收步骤。
- 未访问你的虚拟主机控制面板，未进行公网部署；交付是可上传源码包和本机可运行实例。
- Apache/LiteSpeed的权限与Authorization转发需要在目标主机验收；本机PHP开发服务器不使用 `.htaccess`。
- 未做大规模并发负载、长期运行、移动Safari或旧版浏览器兼容测试。支持目标是现代Chrome/Edge/Firefox/Safari，首批小范围邀请内测。
- 没有真人平衡数据。预算只是准入规则，不保证先后手公平或所有组合强度一致。
- 全部32场自动对局验证可执行性与状态不变量，机器人只是一种有限策略，不构成穷尽性规则证明。

新增积木后应补充相应边界与组合测试，并运行整套测试；不要仅靠网页能点动就认为技能正确。
