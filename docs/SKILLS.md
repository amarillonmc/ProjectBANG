# 自创人物、限定心象与技能积木

当前规则版本为 **0.2.0-alpha**。机制词表来自 [SkillBlocks.php](../src/SkillBlocks.php)，由服务端验证器、解释器和工坊共同使用。本次“加帕里 · 经典交响”提供 38 位角色、76 张 IP 心象和 35 组命名技能拼图；具体搭配、借鉴来源及改编差异见 [KF3_CLASSICS.md](content/KF3_CLASSICS.md)。

## 一、从角色库到自己的作品

1. 在角色库按名称、系列或技能检索角色，阅读技能、配套心象和创作缘由。可以选为出战构筑、编辑整套，也可以仅载入人物，保留正在编辑的 13 张心象及顺序。
2. 在工坊修改人物编号、名字、称号、系列、颜色、4～7 点体力和可选冷暖翻面。从立绘库选择原有四张通用图或本次 38 张角色图。
3. 每个人物最多两个技能。可以从经典拼图库载入并继续修改时机、条件、次数、费用和效果；也可从空白技能开始。普通技能含 1～3 个效果，转化技能使用独立的来源/结果字段。
4. 编排 A～K 各一张的 13 张心象。列表顺序就是从顶到底的抽取顺序，移动槽位不会改变点数。普通类型仍受该点数候选限制。
5. 每副最多四张限定牌。可以从 76 张主题牌中选取，编辑卡名、限定系列、可选角色编号、失配后的普通牌类型和效果。替换心象拼图保留原槽位点数和位置。
6. 阅读工坊生成的效果说明与预算，执行服务端校验后保存。允许自创的房间可以选用；已开局房间保留开局时的构筑快照。

技能和心象可以分别收藏到浏览器本地拼图库，继续编辑、导出为 JSON、在另一设备导入；每类最多收藏 100 项。收藏和导入经过服务端结构校验，完整构筑保存时仍要检查组合预算。

这里的“宏 / macro / 命名拼图”是**可复制的数据模板**。载入后成为普通的技能或心象数据，不是运行时调用，不支持宏嵌套、递归、任意脚本或自动解释自然语言。修改一个副本不会追改原模板或其他作品。只有新增一种解释器尚不支持的底层机制才需要开发代码，使用和组合现有拼图不需要。

## 二、触发时机、次数与条件

每项技能的 `limit` 是整数 **1 或 2**，缺省为 1；含义是每个**全局回合**最多发动多少次，任何一名角色的新回合都会开启新计数。它不是整轮次数，也不是一次行动内无限触发。两项技能各自计数，预算会乘上次数上限。

| trigger | 时机 | target 关联角色 |
| --- | --- | --- |
| `active` | 自己的出牌阶段主动发动 | 玩家指定的存活角色，缺省自己 |
| `turn_start` | 自己的回合开始，标准摸牌前 | 自己 |
| `turn_end` | 自己的回合结束，完成必要弃牌后 | 自己 |
| `after_damage` | 自己实际受到伤害后 | 伤害来源 |
| `after_attack` | 自己的攻击实际造成伤害后 | 受伤目标 |
| `on_defend` | 完成整次防御后（含能量爆发的防御） | 来源角色 |
| `after_play_attack` | 使用攻击牌后、进入其防御等待前 | 本次用牌目标 |
| `after_play_event` | 使用事件牌后，包含有效的限定心象 | 本次用牌目标；未指定则自己 |
| `hand_empty` | 行动及即时效果结算边界，从有手牌变为空手 | 自己 |
| `convert` | 将一张符合来源的手牌转化使用或响应 | 由本次用牌/响应确定 |

自动触发时若来源不存在或已退场，关联目标退回自己；只允许作用于“另一名角色”的效果不会因此对自己发动。主动技能与转化由玩家选择；其余技能满足条件、次数、目标及费用时自动执行。自动费用从左侧手牌与心象顶支付，设计高代价技能时应考虑这一点。

| condition | 判断 |
| --- | --- |
| `always` | 无额外条件 |
| `wounded` | 有效体力低于当前身体上限 |
| `hand_low` | 手牌不超过 2 张 |
| `hand_empty` | 没有手牌 |
| `hand_full` | 手牌不少于当前有效体力 |
| `healthy` | 有效体力等于当前身体上限 |

条件在尝试发动时由服务器检查。`cost.hand` 与 `cost.mind` 各为 0～2，一次发动只支付一次。主动技能可以用 `costCards` 指定手牌费用。次数先记账再结算，避免受伤反应互相无限触发。心坏关闭人物技能；每次行动至多处理 96 个事件/效果，每回合另有 120 次主动行动上限。

## 三、17 种效果

每项效果的结构为 `{op,target,amount,color}`。除表中例外，`amount` 为 1～3 整数。`self` 是技能/卡牌使用者，`target` 是指定或触发关联角色。不要把操作名称推断成可选所有目标，应遵守下表与目录的 `effectMeta.targets`。

| op | 允许目标 | 数量与结算 |
| --- | --- | --- |
| `draw` | self / target | 摸普通牌；普通牌堆用尽时回收普通弃牌 |
| `heal` | self / target | 回复有效体力，不超过身体上限；心坏不能回复 |
| `damage` | self / target | 直接技能伤害，受护盾影响；没有防御响应窗 |
| `recover_mind` | self | 从自己的已耗区按现有顺序取牌放到心象底 |
| `shield` | self / target | 获得护盾，累计上限 6，抵扣后续伤害 |
| `range` | self | 增加攻击范围，累计加成上限 99 |
| `attack_bonus` | self | 增加攻击伤害，累计上限 3 |
| `steal_hand` | target | 从另一角色随机取得手牌，不包含装备或延时区 |
| `discard_hand` | target | 随机弃另一角色手牌，不能指定其暗手牌身份 |
| `give_hand` | target | 将自己的手牌交给另一角色；必须有足量手牌 |
| `draw_to` | self | 数量 1～5；把手牌补到该张数，已有更多牌时不弃牌 |
| `extra_attacks` | self | 增加普通攻击使用额度，累计额外额度上限 9；仍需攻击牌 |
| `lose_health` | self | 失去有效体力，忽略护盾、不触发受伤技能，正常结算濒死 |
| `attack` | target | 对范围内另一角色发起可防御的虚拟攻击，遵守冷暖目标限制；不消耗通常攻击额度 |
| `scry` | self | 私密查看普通牌顶 1～3 张，按选择顺序全部放回牌顶 |
| `draw_discard` | self / target | 从普通弃牌堆顶依次取得牌；不足时取尽，不凭空补牌 |
| `double_defense` | self | 数量固定为 1；自己的攻击需要连续两次成功防御 |

护盾、范围加成、攻击增伤、额外攻击次数和双重防御在受益者下次自己的回合开始清空。双重防御不叠成三次；第一张防御只减少一次需求，完整抵消后才触发 `on_defend`。若只完成一次后承受攻击，仍结算整次伤害。

`color` 只允许 `cool`、`warm`、`neutral`，影响 `damage` 和 `attack`；其他效果保留该字段但无颜色作用。`attack` 提供响应窗，`damage` 是直接伤害，两者不可互换称呼。系列模式下伤害仍按该模式规则计算。

## 四、转化技能

转化技能使用 `trigger: "convert"`，`effects` 必须为空数组（导入时可省略，规范化后补齐），并提供 `conversion`。它不能同时携带普通效果。下面是一个技能对象，可载入人物的技能位置：

```json
{
  "name": "攻守相通",
  "trigger": "convert",
  "condition": "always",
  "cost": {"hand": 0, "mind": 0},
  "effects": [],
  "limit": 1,
  "conversion": {"from": "attack", "to": "defense"}
}
```

| 字段 | 可选值 |
| --- | --- |
| conversion.from | `attack` 攻击牌、`defense` 防御牌、`red` 红桃/方块、`black` 黑桃/梅花、`hand` 任意手牌 |
| conversion.to | `attack_neutral` 无色攻击、`defense` 防御 |

转化必须消耗一张符合条件的**实体手牌**，此外再支付技能费用；转化牌不能同时充当手牌费用。花色转化识别实体的 `suit`，没有花色的心象不满足红/黑条件。攻击/防御来源按当前使用者实际可用牌型判断，包括限定牌失配后的 fallback。

出牌阶段使用转化攻击占用通常攻击额度；响应“潜能爆发”时也可按合法动作转化打出攻击，这种响应不算主动攻击。转化防御只在对应响应窗口使用。原实体的 UID、普通/心象来源和心象所有者不会被转化重写，弃置后仍去应去的区域。对局操作沿用 `play` 或 `respond`，携带技能下标 `conversion`，不是主动 `skill` 操作。

## 五、赠牌、等待与私密信息

**赠牌。** 主动技能界面可分别选择费用牌和赠送牌；赠牌数是本组全部 `give_hand` 数量之和，使用 `selection` 按效果顺序分配。未选择时，支付费用后从左侧手牌依次赠送。手牌不足、数量错误、重复 UID 或把费用牌再次选作赠牌都会被拒绝。取得或赠送心象不会改变其原所有者。

**顺序。** 效果按照数组顺序执行。`attack` 会暂停后续效果，等待目标完成防御或承受伤害，再继续；`scry` 会等待查看者确认牌序后继续。例如“攻击 → 赠牌”必须先结束攻击响应，“观星 → 摸牌”从重新排好的牌顶摸牌。攻击在轮到结算时若已无合法目标会失效。响应期间手牌可能被其他反应移走，已经排队的赠牌届时无法完成会终止该组剩余效果，避免卡住回应者。

**事件。** 有效的限定心象走事件队列；对回合外且持有“攻守同盟”的目标，服务器提供事件取消窗口。事件通过后才执行其效果。人物主动技能本身不自动变成可被“攻守同盟”取消的事件；其中的 `attack` 仍可防御。

**观星。** `scry` 查看的是普通牌堆，只有当前查看者的 `pending.cards` 含这些牌。其他参与者只看到有人正在处理观星，不收到暗牌 UID、次序或可操作选项。确认时必须提交全部牌且每张仅一次，**列表第一张成为最上方**；不支持放到底部。网页按点击勾选次序显示回顶顺序，默认响应保留原顺序。查看者失效或对局结束时，未提交牌按原次序归还，不能把暂存牌遗失或公开。

`hand_empty` 在行动和即时结算边界检查，不在支付中途抢先摸牌。前一个效果导致死亡、胜负或心坏时，后续效果仍要遵守当前存活、治疗及区域规则。

## 六、IP 限定、角色绑定与图像

限定牌的 `custom.series` 必须与当前使用者的系列完全一致，才能使用自定义效果。可选 `custom.characterId` 进一步要求使用者的 `character.id` 一致；任一不符即按 `fallback` 的普通牌规则使用。名字不是绑定依据，改卡名或角色名不会获得对应能力，角色 ID 也不是权限或稀有度凭证。

本包全部 76 张心象限定系列“动物朋友3”，其中 8 张额外绑定角色。新增白虎与朱雀各带两项技能、两张心象，补齐四神，继续复用已有 35 组命名拼图。每位预设自带两张主题心象，创作者仍可在每副最多四张的限制内替换与组合。复制到其他 IP 时可编辑系列和绑定字段，并重新验证。

`character.art` 可以是原图集编号 0～3，也可以是目录中的字符串立绘 ID，例如 `kf3_0042`。字符串必须匹配 `[a-z][a-z0-9_]{0,63}`；客户端只从 `catalog.arts` 找对应资源，未知 ID 回退到通用图，不能把任意 URL 写入该字段。插画与人物编号分别存储，改立绘不会自动换技能或角色绑定。

## 七、版本、预算与边界

导入不带 `rulesVersion` 或标为 `0.1.0-alpha` 的旧构筑，仍走相同服务端校验，规范化输出标为 `0.2.0-alpha`；缺省次数补为 1，旧数字插画编号继续可用。未知版本被拒绝。版本升级不会按牌名替换效果、改排心象或追改已开始对局的构筑快照。

进行中的旧对局会在下一次操作或超时检查时显式升级：补齐新增状态、保留牌区和伤害、将旧次数记录转换为当前格式，并写入一次迁移日志和 `migratedFromRulesVersion`。尚未升级的只读视角保留旧 `rulesVersion`，另给出 `engineRulesVersion` 与 `rulesUpgradePending`；未知对局版本会被拒绝。

人物预算上限 18，全部限定牌合计上限 24，单张限定牌上限 12。人物体力、翻面、自动触发、转化来源、次数、费用和效果共同计费；无色直接伤害/攻击每点另加预算。以服务端返回值为准，本地估算仅用于编辑预览，预算通过不代表强度完全相等。

当前可复用的范围包括上述 17 种效果、10 种时机与 6 种条件。仍不支持任意看他人暗手牌、任意判定条件分支、牌顶置底、多目标自由选择、嵌套效果、修改普通牌池或胜利条件。正式成品中的近似改编会写明差异，例如护盾并非木桶判定、有限攻击额度并非无限咆哮；请以 [已实装清单](content/KF3_CLASSICS.md) 和服务端生成说明为准。
