# 自创人物、限定心象与技能积木

当前规则版本为 **0.5.0-alpha**。机制词表来自 [SkillBlocks.php](../src/SkillBlocks.php)，由服务端验证器、解释器和工坊共同使用。三个内容包合计提供 104 位 IP 角色、208 张 IP 心象和 107 组内容包命名技能拼图；另新增 32 组通用机制示例，另保留 4 位原创示例。具体搭配见 [KF3_CLASSICS.md](content/KF3_CLASSICS.md) 、[MAGIRECO_EXPANSIONS.md](content/MAGIRECO_EXPANSIONS.md) 和 [ADVENTURE_KING.md](content/ADVENTURE_KING.md)。冒险王的原创技能在原来源位置展示设计理由，人设资料另附链接。魔法纪录扩展包的 30 个命名拼图取材于一将成名、SP、阴、雷，官方来源、采用版本和改编差异见 [SGS_EXPANSION_MECHANICS.md](content/SGS_EXPANSION_MECHANICS.md)。

## 一、从角色库到自己的作品

1. 在角色库按名称、系列或技能检索角色，阅读技能、配套心象和创作缘由。可以选为出战构筑、编辑整套，也可以仅载入人物，保留正在编辑的 13 张心象及顺序。
2. 在工坊修改人物编号、名字、称号、系列、颜色、由服务器配置允许的体力（默认 1～98）和可选冷暖翻面。从立绘库选择通用图或内容包角色图。
3. 不再有两个技能的设计限制；技能数只受可配置资源上限约束（默认 98）。可以从拼图库按来源包筛选、检索并载入，继续修改时机、条件、次数、费用和效果；也可从空白技能开始。普通技能含 1～98 个效果节点（默认配置，计入嵌套节点），转化技能使用独立的来源/结果字段。
4. 编排 A～K 各一张的 13 张心象。列表顺序就是从顶到底的抽取顺序，移动槽位不会改变点数。普通类型仍受该点数候选限制。
5. 十三个位置均可使用限定牌，只检查单牌和总预算。可以从 208 张主题牌中按系列筛选，编辑卡名、限定系列、可选角色编号、失配后的普通牌类型和效果。限定牌可选事件、装备、延时基本或延时事件，装备再选武器、防具、装置槽；编辑器只显示该类别允许的积木。替换心象拼图保留原槽位点数和位置。
6. 工坊同时显示自然语言与结构描述；角色库和牌桌可切换两种说明，偏好保存在本浏览器。阅读效果说明与预算，执行服务端校验后保存。允许自创的房间可以选用；已开局房间保留开局时的构筑快照。

技能和心象可以分别收藏到浏览器本地拼图库，继续编辑、导出为 JSON、在另一设备导入；每类最多收藏 100 项。收藏和导入经过服务端结构校验，完整构筑保存时仍要检查组合预算。

这里的“宏 / macro / 命名拼图”是**可复制的数据模板**。载入后成为普通的技能或心象数据，不是运行时调用，不支持宏嵌套、递归、任意脚本或自动解释自然语言。修改一个副本不会追改原模板或其他作品。只有新增一种解释器尚不支持的底层机制才需要开发代码，使用和组合现有拼图不需要。

## 二、触发时机、次数与条件

每项技能的 `limit` 为 0～`unlimitedUses` 的整数；0（也为缺省值）表示设计上的不限次数，运行时受服务器保险上限保护，默认 98。正数表示明确的设计限制。`limitScope` 可选 `turn`（每个全局回合，缺省）、`owner_turn`（自己的回合周期）、`game`（整局）。次数先记账、后结算，重连不重置。`passive` 是实时持续能力，不支付费用、不消耗次数，必须设置 `limit: 0`。

| trigger | 时机 | target 关联角色 |
| --- | --- | --- |
| `passive` | 持续检查条件并修改属性 | self / allies / enemies / everyone，见积木白名单 |
| `active` | 自己的出牌阶段主动发动 | 玩家指定的存活角色，缺省自己 |
| `turn_start` | 自己的回合开始，标准摸牌前 | 自己 |
| `turn_end` | 自己的回合结束，完成必要弃牌后 | 自己 |
| `after_damage` | 自己实际受到伤害后 | 伤害来源 |
| `after_attack` | 自己的攻击实际造成伤害后 | 受伤目标 |
| `on_defend` | 完成整次防御后（含能量爆发的防御） | 来源角色 |
| `after_play_attack` | 使用攻击牌后、进入其防御等待前 | 本次用牌目标 |
| `after_play_event` | 使用事件牌后，包含有效的事件心象，不包含装备心象 | 本次用牌目标；未指定则自己 |
| `hand_empty` | 行动及即时效果结算边界，从有手牌变为空手 | 自己 |
| `convert` | 将符合来源与数量的实体素材转化使用或响应 | 由本次用牌/响应确定 |
| `on_targeted` | 成为攻击目标时、进入防御响应前 | 攻击者 |
| `ally_targeted` | 距离 1 内另一名同阵营角色成为攻击目标 | 被攻击的友方；不包含自己 |
| `after_play_card` | 主动使用一张实体手牌后，包含装备、延时及转化出牌 | 本次用牌目标；未指定则自己 |
| `after_lose_equipment` | 装备被移除的即时效果组结算后 | 移除者；自行卸除时为自己 |
| `after_equip` | 主动装备一张手牌后，包含延时基本牌和真正装备 | 自己 |

自动触发时若来源不存在或已退场，关联目标退回自己；只允许作用于“另一名角色”的效果不会因此对自己发动。主动技能与转化由玩家选择；其余触发技能缺省锁定执行；设置 `optional: true` 则显示发动 / 放弃窗口，接受后才支付费用和记次数。持续技能不可选择发动。自动费用从左侧手牌与心象顶支付，设计高代价技能时应考虑这一点。

| condition | 判断 |
| --- | --- |
| `always` | 无额外条件 |
| `wounded` | 有效体力低于当前身体上限 |
| `hand_low` | 手牌不超过 2 张 |
| `hand_empty` | 没有手牌 |
| `hand_full` | 手牌不少于当前有效体力 |
| `healthy` | 有效体力等于当前身体上限 |
| `played_two` / `played_three` | 本全局回合已主动使用至少 2 / 3 张实体手牌 |
| `played_hp` | 本全局回合主动用牌数不少于自己的当前有效体力 |
| `first_card` | 本全局回合主动用牌计数恰为 1；用于 `after_play_card` 可表达首张 |
| `same_rank_or_suit` | 最近两张主动用牌的实体点数相同，或具有相同非空花色 |
| `first_damage` / `repeat_damage` | 本全局回合实际受到伤害的次数恰为 1 / 至少 2 |
| `has_equipment` | 自己装备区非空，无需成熟 |
| `has_true_equipment` | 自己至少有一件生效的真正装备心象，不包含延时基本牌 |
| `mind_low` | 自己的心象储备不超过 4 张；心坏仍关闭人物技能 |
| `hand_same_color` | 自己至少有两张手牌，且每张均有红桃/方块或每张均有黑桃/梅花 |

用牌计数只记录主动 `play`：响应、主动技能、卸除装备与虚拟攻击不计入。点数和花色读取实体牌，不读取转化后的牌名或人物冷暖颜色；无花色心象可以比较点数，但不能参与同花色或同红黑手牌条件。减伤/护盾完全抵消的伤害和失去体力不增加受伤次数。所有这些计数在每个全局回合开始清零。条件是状态判断；例如 `first_card` 放在主动技能上表示“本回合目前恰好用过一张牌”，不产生额外时机。

条件在尝试发动时由服务器检查。`cost.hand` / `cost.mind` 为 0～`maxAmount`，手牌还支持 `all`（全部手牌）和 `chosen`（自己选任意正数张）。主动技能通过 `costCards` 指定费用，`paid_hand` 数量等于实际支付数。自动费用采用左侧默认选择。单次行动处理上限默认为 4096，每回合主动动作上限为 512，均可在配置中修改。

## 三、基础效果与数量

每项效果的结构为 `{op,target,amount,color}`。数值效果的 `amount` 为 1～`maxAmount`（默认 98）整数；选择、翻转、额外回合等单次操作固定为 1。下表列旧有基础积木，新机制见后文。`self` 是技能/卡牌使用者，`target` 是指定或触发关联角色。不要把操作名称推断成可选所有目标，应遵守下表与目录的 `effectMeta.targets`。

| op | 允许目标 | 数量与结算 |
| --- | --- | --- |
| `draw` | self / target | 摸普通牌；普通牌堆用尽时回收普通弃牌 |
| `heal` | self / target | 回复有效体力，不超过身体上限；心坏不能回复 |
| `damage` | self / target | 直接技能伤害，受护盾影响；没有防御响应窗 |
| `recover_mind` | self | 从自己的已耗区按现有顺序取牌放到心象底 |
| `shield` | self / target | 获得护盾，累计上限 maxAmount，抵扣后续伤害 |
| `range` | self | 增加攻击范围，累计加成上限 maxAmount |
| `attack_bonus` | self | 增加攻击伤害，累计上限 maxAmount |
| `steal_hand` | target | 从另一角色随机取得手牌，不包含装备或延时区 |
| `discard_hand` | target | 随机弃另一角色手牌，不能指定其暗手牌身份 |
| `give_hand` | target | 将自己的手牌交给另一角色；必须有足量手牌 |
| `draw_to` | self | 把手牌补到该张数，已有更多牌时不弃牌 |
| `extra_attacks` | self | 增加普通攻击使用额度，累计额外额度上限 maxAmount，实际攻击次数不超过 unlimitedUses；仍需攻击牌 |
| `lose_health` | self | 失去有效体力，忽略护盾、不触发受伤技能，正常结算濒死 |
| `attack` | target | 对范围内另一角色发起可防御的虚拟攻击，遵守冷暖目标限制；不消耗通常攻击额度 |
| `scry` | self | 私密查看普通牌顶 指定数量的牌，按选择顺序全部放回牌顶 |
| `draw_discard` | self / target | 从普通弃牌堆顶依次取得牌；不足时取尽，不凭空补牌 |
| `double_defense` | self | 数量固定为 1；自己的攻击需要连续两次成功防御 |
| `sequester_hand` | target | 随机暂置另一角色指定数量手牌，不足取尽，本全局回合结束归还；暂置牌不能被使用或支付费用 |
| `discard_equipment` | self / target | 移除指定数量最早进入装备区的牌，保留宝藏反噬；自弃必须有足量装备 |
| `damage_guard` | self / target | 每次伤害减少指定数值，总减伤上限 maxAmount，先于护盾计算；不会消耗，至受益者下次自己的回合开始清空 |
| `hand_lock` | target | 数量固定 1；另一角色本全局回合不能使用或打出手牌，包括转化和攻守同盟响应 |
| `inspect_hand` | target | 私密随机查看他人指定数量手牌，不足取尽，确认后续接，不移走实体 |
| `scry_mind` | self | 私密重排指定数量心象顶牌；等待期间仍留在心象区 |
| `cycle_mind` | self | 将指定数量心象顶牌按原序放到底部 |
| `draw_mind` | self | 将指定数量心象顶牌加入手牌，抽空立即心坏 |
| `recall_equipment` | self | 收回指定数量最早装备到手牌，保留归属、失装触发及宝藏伤害 |
| `break_shield` | target | 削去他人指定数量现有护盾；不造成伤害，不移除御伤 |
| `equip_range` | self | 仅武器/装置：持续增加指定范围，心坏仍为 0 |
| `equip_damage` | self | 仅武器，每个自己回合周期首次结算攻击伤害增加指定数量，拆装不刷新 |
| `equip_shield` | self | 仅防具：自己回合开始，旧盾清空后获得 指定点数的护盾 |
| `equip_draw` | self | 仅装置：自己回合开始摸指定数量普通牌 |
| `equip_distance` | self | 仅防具：他人攻击自己时距离增加指定数值，不改变邻近支援 |

最后五种积木只能用于装备心象，不能放进人物技能或事件。同一装备不能重复同种效果。`custom.kind: "equipment"` 必须同时提供 `slot: "weapon" / "armor" / "gadget"`；缺省 `kind` 是事件。事件不允许 `slot` 字段。

三个真实装备槽各容纳一件，与延时基本牌共用装备区；同槽替换将旧件送到原所有者的已耗区并触发失装。范围与距离立即生效，周期护盾和摸牌要等到自己的回合开始，入场不会额外结算。增伤被护盾完全抵消也消耗本周期次数，成功防御则不消耗。拆除立即停止持续加成及未来周期收益，已获得的手牌/护盾保留。心坏不关闭装备能力，但攻击范围仍为 0。装备不能通过延时基本牌的主动卸除按钮使用，可由收回、拆除、替换等效果移走。

护盾、范围加成、攻击增伤、额外攻击次数和双重防御在受益者下次自己的回合开始清空。重复使用 double_defense 不叠加；passive_double_defense 可额外增加一次需求。第一张防御只减少一次需求，完整抵消后才触发 `on_defend`。若只完成一次后承受攻击，仍结算整次伤害。

封手不阻止弃牌、赠牌、将手牌置底、支付技能手牌费用、从心象判定或使用已装备的回避/加速；它也不取消已发出的攻击。锁定当前行动者时，会禁止其接下来主动使用手牌。封手在本全局回合结束时统一解除，即使施加者已出局、技能心坏或到达事件预算也不会延续到下一回合。

持续减伤不是护盾、判定防御或攻击免疫；增伤后的伤害超过减伤数仍会生效，失去体力忽略两者。怀橘命名拼图每次需要消耗一张心象，不能在心坏后持续补充。一次已经获得的减伤仍持续到下一次自己的回合；心坏不会追溯撤销已经结算的效果。

`color` 只允许 `cool`、`warm`、`neutral`，影响 `damage` 和 `attack`；其他效果保留该字段但无颜色作用。`attack` 提供响应窗，`damage` 是直接伤害，两者不可互换称呼。系列模式下伤害仍按该模式规则计算。

## 四、转化技能

转化技能使用 `trigger: "convert"`，`effects` 必须为空数组（导入时可省略，规范化后补齐），并提供 `conversion`。它不能同时携带普通效果。下面是一个技能对象，可载入人物的技能位置：

```json
{
  "name": "攻守相通",
  "trigger": "convert",
  "condition": "always",
  "cost": {"hand": 0, "mind": 0},
  "effects": [],
  "limit": 1,
  "conversion": {"from": "attack", "to": "defense"}
}
```

| 字段 | 可选值 |
| --- | --- |
| conversion.from | `attack` 攻击牌、`defense` 防御牌、`red` 红桃/方块、`black` 黑桃/梅花、`hand` 任意牌；另有四种花色、`basic`、`event`、`equipment` 类型过滤 |
| conversion.to | `attack_neutral` 无色攻击、`defense` 防御 |

转化消耗符合过滤条件的实体素材；`zone` 支持 `hand`（默认）、`hand_equipment`、`pile`（需要 `pile` 名称），`count` 默认 1，`match` 支持 `any`、`same_suit`、`same_color`，此外再支付技能费用；转化牌不能同时充当手牌费用。花色转化识别实体的 `suit`，没有花色的心象不满足红/黑条件。攻击/防御来源按当前使用者实际可用牌型判断，包括限定牌失配后的 fallback。

出牌阶段使用转化攻击占用通常攻击额度；响应“潜能爆发”时也可按合法动作转化打出攻击，这种响应不算主动攻击。转化防御只在对应响应窗口使用。原实体的 UID、普通/心象来源和心象所有者不会被转化重写，弃置后仍去应去的区域。对局操作沿用 `play` 或 `respond`，携带技能下标 `conversion`，不是主动 `skill` 操作。

## 五、赠牌、等待与私密信息

**赠牌。** 主动技能界面可分别选择费用牌和赠送牌；赠牌数是本组全部 `give_hand` 数量之和，使用 `selection` 按效果顺序分配。未选择时，支付费用后从左侧手牌依次赠送。手牌不足、数量错误、重复 UID 或把费用牌再次选作赠牌都会被拒绝。取得或赠送心象不会改变其原所有者。

**顺序。** 效果按照数组顺序执行。`attack` 会暂停后续效果，等待目标完成防御或承受伤害，再继续；`scry` 会等待查看者确认牌序后继续。例如“攻击 → 赠牌”必须先结束攻击响应，“观星 → 摸牌”从重新排好的牌顶摸牌。攻击在轮到结算时若已无合法目标会失效。响应期间手牌可能被其他反应移走，已经排队的赠牌届时无法完成会终止该组剩余效果，避免卡住回应者。

**事件。** 有效的事件心象走事件队列；装备心象直接进入自己的装备区。对回合外且持有“攻守同盟”的目标，服务器提供事件取消窗口。事件通过后才执行其效果。人物主动技能本身不自动变成可被“攻守同盟”取消的事件；其中的 `attack` 仍可防御。

**观星。** `scry` 查看的是普通牌堆，只有当前查看者的 `pending.cards` 含这些牌。其他参与者只看到有人正在处理观星，不收到暗牌 UID、次序或可操作选项。确认时必须提交全部牌且每张仅一次，**列表第一张成为最上方**；不支持放到底部。网页按点击勾选次序显示回顶顺序，默认响应保留原顺序。查看者失效或对局结束时，未提交牌按原次序归还，不能把暂存牌遗失或公开。

**暂置。** `sequester_hand` 从目标手牌中随机取牌，保存在该持有者的独立暂置区。持有者的 `me.sequestered` 可见牌，其他人仅见 `sequesteredCount`，发动者也不能窥视。正常回合末要等 `turn_end` 的观星/攻击等响应全部结束才归还，然后开启下个回合。持有者出局时普通牌进弃牌、心象进其原所有者的已耗区；施加者出局不改变持有者归还权。提前胜负或 300 回合平局也会清理暂置与封手。心象的原所有者从不被改写。

**受攻与失装。** `on_targeted` 先于防御响应，`ally_targeted` 随后按座次检查；反应中的观星或虚拟攻击先结算，再恢复原攻击，不会重复宣布同一攻击目标。所有攻击事件（包括拳击/虚拟攻击）支持这两个时机；能量爆发的群体伤害不是攻击。失去装备在即时结算边界触发，不能在卸除费用支付中途插入；因出局清空装备不会再触发死者技能。

`hand_empty` 在行动和即时结算边界检查，不在支付中途抢先摸牌。前一个效果导致死亡、胜负或心坏时，后续效果仍要遵守当前存活、治疗及区域规则。

## 六、IP 限定、角色绑定与图像

限定牌的 `custom.series` 必须与当前使用者的系列完全一致，才能使用自定义效果。可选 `custom.characterId` 进一步要求使用者的 `character.id` 一致；任一不符即按 `fallback` 的普通牌规则使用。名字不是绑定依据，改卡名或角色名不会获得对应能力，角色 ID 也不是权限或稀有度凭证。

“动物朋友3”包有 76 张心象，其中 8 张额外绑定角色；“魔法纪录”包有 72 张心象，其中 10 张额外绑定角色；“冒险王”包有 60 张心象（22 张真正装备），其中 6 张额外绑定角色。每位预设自带两张主题心象，创作者可在十三个位置中自由替换与组合，遵守预算。复制到其他 IP 时可编辑系列和绑定字段，并重新验证。库中的心象参考可列出多个原型与通用积木，它们是可独立编辑的事件或装备组合，不承诺逐字复刻原武将技能。

`character.art` 可以是原图集编号 0～3，也可以是目录中的字符串立绘 ID，例如 `kf3_0042`。字符串必须匹配 `[a-z][a-z0-9_]{0,63}`；客户端只从 `catalog.arts` 找对应资源，未知 ID 回退到通用图，不能把任意 URL 写入该字段。插画与人物编号分别存储，改立绘不会自动换技能或角色绑定。

## 七、版本、预算与边界

不带规则版本以及 0.1～0.4 的旧构筑均可导入，重新校验并规范化至 0.5；已有明确次数保留，缺省次数为不限。旧对局首次继续时迁移成熟时间：未携带新成熟参数的非拳击延时基本牌减少原来额外的一回合等待；显式参数和拳击保留。迁移幂等，未知版本拒绝。

进行中的旧对局会在下一次操作或超时检查时显式升级：补齐新增状态、保留牌区和伤害、将旧次数记录转换为当前格式，并写入一次迁移日志和 `migratedFromRulesVersion`。尚未升级的只读视角保留旧 `rulesVersion`，另给出 `engineRulesVersion` 与 `rulesUpgradePending`；未知对局版本会被拒绝。

默认人物预算 18、全部限定牌合计 24、单张限定牌 12，可在 `config.php` 的 `rules` 中分别配置 `characterBudget`、`customBudget`、`customCardBudget`。内置范例不因开放配置而修改。人物体力、翻面、自动触发、转化来源、次数、费用和效果共同计费；无色直接伤害/攻击每点另加预算。以服务端返回值为准，本地估算仅用于编辑预览，预算通过不代表强度完全相等。

当前有 73 种效果、26 种时机、26 种简单条件和结构化比较条件。按用户确认，保留本游戏基础规则，参考当前三国杀 OL 尽量等价还原技能机制；逐项能力、来源版本与仍缺少的机制见 [OL 覆盖审计](content/SGS_OL_COVERAGE.md)。

## 八、0.5 结构化机制

动态数量可用 `all`、`hand`、`hp`、`lost_hp`、`target_hand`、`paid_hand`、`paid_equipment`、`paid_cards`，或 `mark:名称`、`pile:名称`。数值在轮到该效果时读取；三个 paid 数值在支付前分别绑定本次实际弃置的手牌数、装备数、两者总数，经过响应与重连不改变。`all` 对赠牌、装备收回等读取现有区域，对攻击额度等表示配置上限；摸牌的 `all` 最多摸 maxAmount，不表示无限牌堆。

简单条件新增 `hp_not_lowest`（有角色体力更低）、`no_equipment`、`outside_turn`。结构化条件例如 `{"value":"mark","key":"觉醒","cmp":"ge","amount":3}`；`value` 可读取 hp、max_hp、lost_hp、hand、mind、mark、pile、played、damage_taken、pindian_win，比较符为 eq/ne/lt/le/gt/ge。`{"all":[条件…]}` / `{"any":[条件…]}` 组合条件，最多嵌套 12 层；网页能编辑导入的复合条件。

| 拼图 | 附加字段与语义 |
| --- | --- |
| `choose` | `options: [{label,effects},…]`，至少两项；target 为选择者。等待选择一个分支，再继续外层后续效果；无法执行的选项不会列出 |
| `branch` | `condition, then, else`；仅执行一边，空分支允许 |
| `choose_targets` | `pool: everyone/others/allies/enemies`、`effects`；选择至多 amount 个不同合法目标，按点击顺序执行，其中 target 为每个所选角色 |
| `judge` | `filter, then, else, obtain, repeat`；从普通牌顶判定，成功可获得判定牌、询问是否继续；重复上限为 unlimitedUses |
| `passive_retrial` | 仅持续技能。`filter` 指定素材过滤，`zone: hand/hand_equipment`，`exchange` 指定是否获得旧判定牌。按座次提供改判窗口，最后判定牌决定结果；也适用于普通延时事件和加速判定 |
| `pindian` | `then, else`；双方各暗选一张手牌，同时展示比较点数。严格大于才赢，平局进入 else；所用牌按原归属弃置 |
| `add_mark` / `remove_mark` | `key` 指定命名资源。持久化，数值 0～maxAmount；不与冷暖伤害指示物混用 |
| `store_pile` | `key, visibility: public/private`；持有者选手牌放入专属区，保留 UID 和原归属；同名区公开性不可改变 |
| `take_pile` | `key`；持有者选择并按提交顺序取回指定数量，不足时取尽 |
| `exchange_hands` / `exchange_equipment` | 与另一角色整体交换；装备按接收者回合计数重新成熟，触发失装和宝藏代价 |
| `duel` | 目标先打出攻击，双方交替响应；首次放弃者受到 amount 点伤害。可使用合法转换，最多 unlimitedUses 次响应 |
| `lose_max_hp` / `gain_max_hp` | 修改身体上限，不同时回复有效体力；失去上限后体力最多等于新上限，仍需检查濒死 |
| `turn_over` | 独立的行动面翻转；背面角色跳过下一整个自身回合并翻回正面，不等于冷暖翻面 |
| `extra_turn` | 当前回合后按插入顺序执行，结束后恢复原正常座次 |
| `skip_draw` / `skip_play` / `skip_discard` | 跳过下次进入的对应阶段，进入时消费标志 |

判定 filter 支持 any/red/black/heart/not_heart/spade/club/diamond/attack/defense/basic/event/equipment。牌堆、选择、拼点和改判均是可持久化响应窗；对手看不到私密牌堆牌面、首位拼点者尚未揭示的 UID、他人的可操作按钮。

持续积木包括 `passive_attacks/range/hand/hand_penalty/distance_out/distance_in/draw/draw_penalty/guard/no_attack_target/double_defense`。只用于 passive，实时读取存活、心坏、条件与阵营，失效立即撤销光环。正面修正支持 self/allies/enemies/everyone；负面修正仅 self。目标不能被攻击同时作用于普通攻击、虚拟攻击和拳击。额外防御与本回合双重防御可以叠加。

延时心象支持 `kind: persistent/delayed` 和 `maturityTurns`。persistent 装备于自己、成熟后在出牌阶段主动卸除并执行；delayed 放置于角色延时区，成熟后在其回合开始一次性执行，随后弃置。这里没有自动附加人物技能或濒死触发的含义。已有普通心象的成熟参数放在 deck 条目顶层，自创心象放在 custom 内层。

例如“任意张换牌”技能：

```json
{"name":"换牌","trigger":"active","condition":"always","limit":1,"cost":{"hand":"chosen","mind":0},"effects":[{"op":"draw","target":"self","amount":"paid_hand","color":"neutral"}]}
```

## 九、配置、计价与安全边界

将 config.example.php 复制为 config.php，或把其中 `rules` 数组合并进已有配置。未写的键使用默认值；配置只由服务器读取，自创 JSON 无权修改。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| characterBudget / customBudget / customCardBudget | 18 / 24 / 12 | 人物、心象合计、单张心象预算 |
| unlimitedUses | 98 | 不限次数技能的运行保险上限，按所选计数周期重置；也限制判定链和决斗 |
| maxSkills / maxEffects / maxAmount / maxHp | 98 | 构筑与执行的资源上限；maxEffects 计入嵌套节点 |
| unlimitedBudgetWeight | 2 | 不限次触发按此权重计价；持续技能权重为 1 |
| negativeBudgetFloor | -12 | 单人物所有强制负预算合计最多抵扣 12 |
| maxActionsPerTurn / maxResolutionSteps / maxTurns | 512 / 4096 / 300 | 每回合动作数、完整效果链结算步数、平局回合阈值 |

结算步数跨同一效果链的响应、选择和刷新累计，不会每次响应重置。达到保险上限时结束剩余效果链、归还或弃置等待中的实体牌并释放判定占用，已支付费用及已完成效果保留，手记明确记录原因；下一次主动操作或新回合获得新额度。

自身失去体力/上限、持续少摸牌/少手牌上限可以产生负成本。只有无费用、非可选的 passive/turn_start/turn_end，且条件为 always 或 hp_not_lowest 的整体负面技能可返还人物预算。动态数量没有稳定负面代价保证，因此不给负预算。可选负面分支取较高成本，不能用不会选择的惩罚套利。心象负效果只抵扣同一张卡的正效果，最低计零，不能用闲置的惩罚卡免费扩充其他卡预算。分支、反复判定获得牌、多目标效果递归计价。

本版本配置是服务器全局策略，修改后会影响旧构筑再次保存和既有房间后续行动；对局只保存构筑快照，尚未保存完整配置快照。部署时应在无进行中房间时调整规则配置。保险边界不是平衡结论。

## 十、伤害、濒死与死亡窗口

`before_deal_damage`（来源）、`any_before_damage`（从当前回合角色起按座次）、`before_take_damage`（受伤者）在伤害扣除前依序执行。随后计算持续减伤、临时御伤与护盾，实际扣血后进入濒死处理，再依次执行 `after_damage`、`after_deal_damage`、攻击专用 `after_attack`、`any_after_damage`。`damage_point` 最后按实际伤害逐点触发，可以逐点询问是否发动。被取消或被护盾全部抵消的伤害不产生这些受伤后触发。

仅伤害发生前的三个时机可使用 `event_add_damage`、`event_reduce_damage`、`event_set_damage`、`event_cancel`、`event_redirect`、`event_source`。转移保留来源与当前数值，新目标进入自己的受伤前窗口，不重复计算攻击/宝藏加成；同次伤害不允许回到已承受过转移的角色。用 `choose_targets` 选择转移对象。取消伤害不会消耗护盾，不是先伤害再治疗。

动态数量 `event_amount`、`event_original_amount`、`event_point` 读取当前事件；效果目标可引用 `event_source`、`event_target`、`turn_player`。结构化条件可加 `subject` 指定上述角色或 `self`。例如 `{"subject":"event_target","value":"hp","cmp":"le","amount":1}`。不存在的来源不视为自己，针对它的效果跳过。嵌套事件结束后恢复外层事件的来源、目标和数量。

`dying` 与 `any_dying` 在奇迹自动救援及冷暖翻面之前插入；一般治疗依旧不能恢复身体，也受心坏限制。仍然濒死时先确定死亡，执行 `death`（牌区尚未清理），然后弃置剩余区域牌，执行其他存活角色的 `any_death`。死亡时机的回复不会撤销已经确定的死亡。伤害、濒死、死亡事件全部关闭后才判断胜负。来源为空的失去体力也可进入濒死窗口，但不是伤害。

## 十一、混合费用与动态技能

`cost.zone` 为 `hand`（缺省）或 `hand_equipment`，`cost.hand` 数字 / `chosen` / `all` 表示从该区域支付的张数。名称沿用旧协议；混合费用可以任意组合手牌与装备。`paid_cards` 是总支付数，`paid_hand` 仅统计手牌，`paid_equipment` 仅统计装备；`branch` 的 `paid_all_hand` 条件要求支付前至少有一张手牌，且这些手牌全部作为本次费用弃置。这些值在支付前绑定，经历装备反噬、选择与重连也不改变。装备费用照常触发失装与宝藏副作用。

`gain_skill` 需要 `key`（稳定标识）、`skill`（完整技能定义）与 `duration`。`lose_skill` 按 key 移除；`seal_skill` 按 key 暂停，包含持续能力；`copy_skill` 让发动者从目标当前有效技能中选择一项获得。技能定义可选 `key`，未写时移除/封锁按名称匹配；建议需要引用的技能使用唯一标识。相同标识不能被不同定义覆盖。

duration 可为 `permanent`、`turn`（当前全局回合结束）、`owner_turn`（获得者下个自身回合开始）、`source_turn`（发动者下个自身回合开始）。同一技能的永久与临时来源分别保存，临时到期不移除原生或永久来源。失去再获得、反复复制同一来源不会刷新技能自己的次数；复制者与原持有者分别计数。失效槽位保留身份，占用 maxSkills 资源额度。

嵌套技能由同一白名单递归校验并计预算，最多 12 层，嵌套节点计入 maxEffects。工坊可直接编辑获得的技能定义，并同时显示两种说明。以上机制不会新增角色、改变固定牌池或身份胜负规则。
